# G-01 — preview must equal render: **PASS**

Gate G-01 (WP-11, plan Round 5) asks whether what a person approves in the HyperFrames
preview is what HyperFrames renders. Result on 2026-11-09: **pass**. In every one of the five
pairs, the HyperFrames preview and the lossless render show the same text and state and
reach at least 44 dB PSNR. Both negative controls fail the same test, which shows the test
can catch the two failure modes the spike hit.

## What was wrong before

The spike (`drafts/spikes/hyperframes`, plan Round 5) reported preview = render. Its own
frames showed otherwise: at 3.0 s the preview read "0 min" where the render read "20 min",
and the preview used fallback fonts. Three things caused this:

1. **Hand-rolled seek.** The spike seeked with `tl.seek(t)`. GSAP suppresses callbacks on a
   seek by default, so the counter text, which was set only in `onUpdate`, never changed.
   HyperFrames' renderer calls `__player.renderSeek(t)`, and that runs `totalTime(t, false)`,
   so callbacks do fire there.
2. **Fonts outside HyperFrames' compile step.** HyperFrames rewrites system and generic
   families and injects font faces before it captures. Some of those faces it fetches from
   Google Fonts. The spike's preview loaded the raw HTML in plain Chrome, so it got whatever
   fonts Chrome had.
3. **Lossy reference.** The spike compared against an H.264 `yuv420p` MP4, so its 24–28 dB
   figure mixed chroma loss with the real differences.

## Method

- **Composition** (`g01/index.html`): 1920×1080, 6 s, 30 fps, built from the spike's three
  primitives: KenBurns (a linear push on a colour-block plate), Stat (a counter from 0 to 20
  starting at 0.3 s and running 1.8 s, `power2.out`) and CaptionBar (three phrases).
  - Fonts are vendored as `@font-face` woff2 (Inter, Newsreader, JetBrains Mono from
    `blocks/fonts/`), with `font-display: block`.
  - HyperFrames reported `Fonts: 5 loaded` and fetched nothing from Google.
  - GSAP comes from HyperFrames' own vendored copy, which it serves for the jsDelivr
    `gsap@3.15.0` URL.
  - **State is a pure function of time.** The counter text is written by the setter of a
    linear "clock" tween that spans the timeline. GSAP writes tweened properties on every
    render, seeks included, so the digits never depend on a callback firing.
- **Preview** = `hyperframes snapshot --at 0.5,1.5,3,4.5,5.9 --no-end`. This is HyperFrames'
  own seek path: it bundles the HTML with its font step, seeks with `__player.renderSeek`,
  then waits for the seek to settle and for `document.fonts`.
- **Reference** = `hyperframes render --format png-sequence`: lossless RGBA PNGs, one per
  frame.
  - HyperFrames makes the page ground transparent in this mode and names it on its
    `@hf-result` line (`reference_background` = `#0D0B0A`).
  - The harness composites each reference frame over exactly that colour before comparing.
  - Frame `n` (0-based) is written as `frame_{n+1:06d}.png`. Each probe time lands exactly on
    frame 15, 45, 90, 135 or 177.
- **Measures** (`g01-metrics.ts`, unit-tested):
  - *Frame PSNR*: FFmpeg's `psnr` filter on the whole RGB frame, average of R, G and B.
  - *Text/state*: ink IoU, which needs no DOM or OCR. In two fixed text regions (the counter
    with its unit, and the caption pill), each frame is converted to grey and thresholded at
    luma 128. All text in the composition is light on dark. The score is the
    intersection-over-union of the "ink" pixels. A different digit, a different caption or a
    different font moves the ink. Anti-aliasing noise only flips a thin edge.
  - *By eye*: the counter and caption crops were put side by side and read (see below).
- **Bar** (fixed before measuring): every pair must have frame PSNR ≥ 35 dB **and** ink IoU
  ≥ 0.95 in both regions. A set passes only if all five pairs pass. G-01 passes only if the
  G-01 set passes **and** both negative controls fail.

## Result (run 2, `g01/evidence/results.md`)

| 1.5 | 45 | 19 min / "Step 1 Breakdown and bibles" | 46.34 | 1.000 | 1.000 | pass |
| 3.0 | 90 | 20 min / "Step 2 Sketch board and key frames" | 44.17 | 1.000 | 0.968 | pass |
| 4.5 | 135 | 20 min / "Step 3 Clips, sound and the final cut" (fading in) | 48.52 | 1.000 | 1.000 | pass |

The counter values match what the composition's own function gives for each time
(`expectedCounter`: 6, 19, 20, 20, 20). Run 1 produced the same numbers to two decimals.

**The one systematic difference is text anti-aliasing.** At 3.0 s the snapshot draws the
caption with LCD (sub-pixel) anti-aliasing. The RGBA PNG reference draws it in greyscale,
because its ground is transparent. Glyph shapes and positions are the same: ink IoU is 0.968
and the residual sits only on glyph edges (`t3-preview.png` vs `t3-render.png`). A delivered
MP4 is `yuv420p`, which is coarser in chroma than this fringe.

## Exact commands

```bash
# Windows, Git Bash. HyperFrames 0.9.19 is installed in the spike folder; nothing is written there.
export HYPERFRAMES_BROWSER_PATH="C:\Program Files\Google\Chrome\Application\chrome.exe"
cd packages/skills/akuko/skills/akuko
node --experimental-strip-types engines/hyperframes/g01.ts \
  --hf <spike>/node_modules/hyperframes/bin/hyperframes.mjs --out <scratch>/g01-run2
# exit 0 = PASS (G-01 passes and both controls fail); results.md, results.json, SHA256SUMS in --out
```

Inside, the harness runs, per composition (`work/g01`, `work/nc-onupdate`):

```bash
node hyperframes.mjs snapshot <work>/<comp> --at 0.5,1.5,3,4.5,5.9 --no-end -o <out>/<comp>/preview-hf --json
node hyperframes.mjs render   <work>/<comp> --format png-sequence -o <out>/<comp>/ref
ffmpeg -i ref/frame_000091.png -f lavfi -i color=c=0x0D0B0A:s=1920x1080 \
  -lavfi "[1:v][0:v]overlay=shortest=1:format=rgb,format=rgb24" -frames:v 1 ref-flat/ref-frame_000091.png
ffmpeg -i preview.png -i ref-flat.png -lavfi "[0:v]format=rgb24[a];[1:v]format=rgb24[b];[a][b]psnr" -f null -
ffmpeg -i frame.png -vf "crop=680:190:620:300,format=gray" -f rawvideo -     # counter region
ffmpeg -i frame.png -vf "crop=980:56:470:956,format=gray" -f rawvideo -      # caption region
```

The two hand-rolled captures use `puppeteer-core` 25.16.0 from the HyperFrames install, with
system Chrome and ANGLE/D3D11. They follow the spike's `capture_browser.mjs`. The jsDelivr
GSAP URL is answered from HyperFrames' vendored copy, so no network is needed.

All of these ran with `HYPERFRAMES_BROWSER_PATH` set to system Chrome. Without it,
HyperFrames' bundled headless shell crashes on Windows (R-9). `estimateRender()` in `cli.ts`
is fitted to the two MP4 runs, at 0.2 s per frame plus 38 s. That gives about 74 s for this
6 s clip and about 8 min for a 70 s film. Treat it as rough: the spike measured 2–3 min per
6 s on the same machine under other load.

## Limits

- One machine, one GPU path. The snapshot and the render both used hardware ANGLE. A
  SwiftShader (`--no-browser-gpu`) or Docker render was not measured.
- "Preview" here means `hyperframes snapshot`, which seeks through the same
  `__player.renderSeek` the renderer uses. The interactive Studio player (`hyperframes
  preview`) runs the same runtime but was not captured frame by frame.
- Audio, video media and shader transitions are not part of this composition.
- CI does not run the harness, because it needs Chrome, FFmpeg and HyperFrames. CI does run
  its pure parts (`g01-metrics.test.ts`): PSNR parsing, ink IoU, the pass/fail rule, frame
  naming and the negative-control rewrite.
