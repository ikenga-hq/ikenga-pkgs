# @ikenga/pkg-mattermost

## 0.3.0

### Minor Changes

- [#137](https://github.com/ikenga-hq/ikenga-pkgs/pull/137) [`e28ba56`](https://github.com/ikenga-hq/ikenga-pkgs/commit/e28ba56b8abac1c230ba0fb08bb2379b78004ae3) Thanks [@nedjamez](https://github.com/nedjamez)! - B5 safety rails and audit. **Breaking for existing configs:** every bot now has a mode ceiling, `maxMode` (`plan` | `acceptEdits` | `bypassPermissions`, default `plan`). A config whose `approvals` block (the default `actingMode: auto` is `acceptEdits`) or `chi.mode` is above it is refused at load with a message naming the bot and the field, never downgraded; set `maxMode: "acceptEdits"` to keep B3 approvals working. A bot with no `chi.mode` now sends `plan` explicitly instead of leaving it to the daemon's `default`. The ceiling is asserted again at every `chi_run` / `chi_resume` call site (thread, resume, approved run, schedule); a stored run above it is not resumed. Every bot writes an append-only audit log, `<dataDir>/audit-<bot>.jsonl` (0600, atomic fsynced appends, size-rotated, SHA-256 hash-chained): config load, gate denials, thread runs requested/started/resumed/finished/cancelled/refused, approvals requested/decided/expired/withdrawn/rejected (with plan hash and approver id and name), and schedule runs. It never holds message text, plans, outputs or secrets. A record is written before each run starts; if it cannot be, the run (and the bridge start) is refused. Optional per-bot mirror of one-line summaries to an audit channel (`audit.channel`, write-only), optional truncated prompt hash (`audit.promptHash`), and `node dist/bridge.js --audit <bot> [--since 24h] [--verify]` to print or verify the log. New `branchPrefix` (for example `rex/`) adds an advisory branch instruction to acting runs; the README has the GitHub ruleset checklist that actually enforces it, an "Enforced where" table, and Ruby's write path as an open item. **A permission mode only binds on `claude-code`** (the only engine the daemon turns it into a flag for): `chi.engine` or a schedule `engine` of anything else is refused unless `maxMode` is `bypassPermissions`, and audit records carry the engine and the effective mode. The audit log takes a lock for concurrent writers and seals a crash-torn last line with an `audit.recovered` record.

## 0.2.0

### Minor Changes

- [#133](https://github.com/ikenga-hq/ikenga-pkgs/pull/133) [`bc77f91`](https://github.com/ikenga-hq/ikenga-pkgs/commit/bc77f91e83a436d8e0f1f15166d30eae8f83f780) Thanks [@nedjamez](https://github.com/nedjamez)! - B2 sessions and threading: a bot configured with a `daemon` and a `chi` section runs each Mattermost thread as a Chi run on the Ikenga daemon (`chi_run` for a new thread, `chi_resume` for replies, `chi_cancel` for "stop"), keeps `root_id -> run_id` in a JSON store across restarts, and reports progress and the result back in the thread. Bots without those sections keep the B1 echo behaviour.

- [#134](https://github.com/ikenga-hq/ikenga-pkgs/pull/134) [`ea61064`](https://github.com/ikenga-hq/ikenga-pkgs/commit/ea610649de3bf277132a9fc37b1b095b774b8345) Thanks [@nedjamez](https://github.com/nedjamez)! - B3 approvals: a bot with an `approvals` block runs each thread turn in the daemon's read-only `plan` mode, posts the plan, and only a 👍 from a configured approver (deny by default, separate from `allowedUsers`) starts a second run in `approvals.actingMode` (`auto` by default). 👎, or no decision within `approvals.timeoutMs` (default 15 min), denies. Pending approvals are persisted (mode 0600) and survive a bridge restart, including their expiry. The Chi run has no pause-for-permission, so per-action prompts are not possible; the README says what the daemon enforces and what the bridge does.

- [#135](https://github.com/ikenga-hq/ikenga-pkgs/pull/135) [`837a92d`](https://github.com/ikenga-hq/ikenga-pkgs/commit/837a92d6f22ef2e95c9f76a43f97c6a64b04826d) Thanks [@nedjamez](https://github.com/nedjamez)! - B4 scheduled posts: a bot may carry `schedules` (name, 5-field UTC cron, channel, task; optional cwd/engine/timeout overrides, `enabled`, `onMissed: once|skip`, `quiet`). At each due time the bridge starts a Chi run in the daemon's read-only `plan` mode, never through approvals even when the bot has them, and posts a header plus the result as a new root post; failures post a short notice. One run per schedule at a time. Last-run state is persisted (mode 0600, atomic) before a run starts, so a restart never double-posts, and at most one missed occurrence per schedule runs after downtime (`once`, or `skip`). Bad cron, a channel outside `allowedChannels` or unknown to Mattermost, duplicate names and a `mode` field are refused at load. `quiet` schedules post only problems plus one OK line per UTC day. Operator CLI: `node dist/bridge.js --run-schedule <bot>/<name>` and `--list-schedules`. `bridge.example.json` ships the Rex weekly standup, Rex box alerts and Ruby daily reply digest pointed at the test channels.
