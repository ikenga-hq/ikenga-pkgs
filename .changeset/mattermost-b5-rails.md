B5 safety rails and audit. **Breaking for existing configs:** every bot now has a mode ceiling, `maxMode` (`plan` | `acceptEdits` | `bypassPermissions`, default `plan`). A config whose `approvals` block (the default `actingMode: auto` is `acceptEdits`) or `chi.mode` is above it is refused at load with a message naming the bot and the field, never downgraded; set `maxMode: "acceptEdits"` to keep B3 approvals working. A bot with no `chi.mode` now sends `plan` explicitly instead of leaving it to the daemon's `default`. The ceiling is asserted again at every `chi_run` / `chi_resume` call site (thread, resume, approved run, schedule); a stored run above it is not resumed. Every bot writes an append-only audit log, `<dataDir>/audit-<bot>.jsonl` (0600, atomic fsynced appends, size-rotated, SHA-256 hash-chained): config load, gate denials, thread runs requested/started/resumed/finished/cancelled/refused, approvals requested/decided/expired/withdrawn/rejected (with plan hash and approver id and name), and schedule runs. It never holds message text, plans, outputs or secrets. A record is written before each run starts; if it cannot be, the run (and the bridge start) is refused. Optional per-bot mirror of one-line summaries to an audit channel (`audit.channel`, write-only), optional truncated prompt hash (`audit.promptHash`), and `node dist/bridge.js --audit <bot> [--since 24h] [--verify]` to print or verify the log. New `branchPrefix` (for example `rex/`) adds an advisory branch instruction to acting runs; the README has the GitHub ruleset checklist that actually enforces it, an "Enforced where" table, and Ruby's write path as an open item. **A permission mode only binds on `claude-code`** (the only engine the daemon turns it into a flag for): `chi.engine` or a schedule `engine` of anything else is refused unless `maxMode` is `bypassPermissions`, and audit records carry the engine and the effective mode. The audit log takes a lock for concurrent writers and seals a crash-torn last line with an `audit.recovered` record.
