Add inbound images: an optional per-bot `media` block lets listed Mattermost users (`allowedUserIds`, ids only) attach PNG or JPEG files to a message. The bridge, which alone holds the Google credential, downloads each file, accepts only PNG/JPEG by declared mime, extension and magic bytes together (SVG, HTML, GIF, WebP and any mismatch are refused), enforces `maxBytes` (default 8 MiB, max 20 MiB) from the metadata and again while streaming, requires the file to belong to the triggering post, and uploads it to a public GCS bucket with `ifGenerationMatch=0` (an existing object is never overwritten) under `<prefix><YYYYMMDD>-<sha256[0..16]>/<sanitized name>`. The OAuth token is minted from the service-account key with an RS256 JWT built in the bridge (no new dependency) and cached. The Claude prompt is the user's text unchanged plus a bridge-written block of sanitized names and public URLs; any refused file or failed upload starts no run and gets a short plain reply (never the key, token or Google's error body). The config names environment variables (`credentialEnv`), never values, and is validated strictly at load; a missing or malformed credential switches media off with one startup error line naming the variable, and the bridge still starts. One `media.file` audit record per file. Bots without the block, and posts without attachments, behave exactly as before. See "Inbound images (`media`)" in the README, including the no-echo steps for loading the key and the rollback.
