Add Mattermost cards for the box outreach sender: an optional `outboxApprovals.outreach` block (off unless `enabled: true`; `exportPath` with `{day}`, `exportLocalTime` default `08:00`, `timezone` default `Africa/Lagos`, `pollMs`). Each poll the bridge reads `outreach_status` and `outreach_replies` from the sender socket (approvals contract r5), posts one pause card (acked with `outreach_pause_ack`, never reposted, rebuilt from the sender after a restart), one card per reply or bounce (cursor saved only after the batch is posted, no double posts), and one daily summary of counts with the sender's export file attached when the bridge can read it. A 👍 on the current pause card sends `outreach_resume` and a :no_entry_sign: on a reply card sends `outreach_optout`, each with the reaction event's user id; the sender decides who may, and a refusal is logged by its code only. Bots and the bridge's own reactions are ignored. Outreach drafts (`outreach:` / `outreach-fu:` ids, outreach field labels, or anything doubtful) no longer get a per-draft outbox card, whether or not the block is on. Cards and logs hold counts, company and assignee names only: never an address, reply text or subject. Adds `uploadFile` and `file_ids` to the Mattermost client.
