Add the bridge upload socket (`media.uploadSocket`), so a renderer on the host can publish a PNG it just rendered without ever holding the Google credential. Optional, and off unless `media.enabled` AND `uploadSocket` are present and the credential loaded. The bridge creates a Unix socket (default `/run/ikenga-mattermost/upload.sock`, born 0600; the bridge grants each account in the required `clients` list (1 to 8 Unix usernames) `rw` with `setfacl -m u:<name>:rw,m::rw`, sets 0660, and verifies the ACL with `getfacl`; any failure removes the socket and leaves the upload socket off while the bridge keeps running; there is no `group` key; a stale node is removed only when connecting to it is refused). Per connection: one JSON line `{"path":...}` (at most 4 KiB, 5 s), answered with one JSON line `{"ok":true,"url","object","sha256"}` or `{"ok":false,"code","message"}` using fixed codes and phrases only (`bad_request`, `not_found`, `outside_source_dir`, `not_regular`, `too_large`, `not_png`, `rate_limited`, `upload_failed`, `media_off`). The file is resolved with `realpath` and must lie inside `sourceDir` (default `/var/lib/ikenga-render/out`); it is checked with `lstat`, then opened `O_NOFOLLOW` and `fstat`ed (regular, one hard link, non-empty, within `maxBytes`, default 10 MiB, max 20 MiB), read through the descriptor and accepted only with the PNG signature. Upload reuses the inbound-image object naming and `GcsUploader` (`ifGenerationMatch=0`, 412 is success). A global token bucket (`ratePerMinute`, default 12), at most 2 uploads in flight and 8 open connections bound the load; one `media.upload` audit record per request carries the basename, hash, size and object, never a path, secret or Google body. Validated strictly at load; the socket is closed and unlinked on shutdown. See "Upload socket (`media.uploadSocket`)" in the README.
