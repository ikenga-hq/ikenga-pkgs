Add per-user policies: an optional `userPolicies` block per bot, keyed by Mattermost user id, lets someone who is not in `allowedUsers` use the bot in the policy's own `channels` with their own `cwd`, `mode` (`default` or `plan`), `systemPrompt` and an explicit `allowedTools` list. Validated at load (unknown tool names, an empty allowlist, a bare or interpreter-only `Bash` rule, unscoped `Read`, writes, network and MCP tools, a user also in `allowedUsers`, a missing `cwd` or `enforcedBy`, a mode above `maxMode`). Members of `allowedUsers` are unchanged, and a user on no list is refused as before. A thread is owned by the session that started it: a different policy cannot resume, cancel or queue behind it. The bridge sends the limits to the daemon as `opts.toolPolicy` on `chi_run`; the daemon does not apply it yet, so each policy must state `enforcedBy` (`daemon` or `settings-file`) and the README gives the daemon contract (`claudeArgsForToolPolicy` is the exact argv) and the probes that pinned it. New operator commands `--list-policies` and `--print-policy <bot>/<user id>`. `maxMode` now also accepts `default`. Configs without `userPolicies` behave exactly as before.
